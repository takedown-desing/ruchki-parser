# Парсер каталогов для ручкидлядверей.рф

Добавляете адрес сайта, нажимаете «Собрать», получаете Excel, который загружается в админку сайта без переделок. Фото сохраняются рядом. Повторный сбор показывает, что изменилось: новые товары, цены, наличие, пропавшие позиции.

## Сайт парсера

**https://takedown-desing.github.io/ruchki-parser/**

Открывается в любом браузере, ничего ставить не нужно. Без входа видно все источники и товары, Excel скачивается. Сбор идёт на серверах GitHub (задача «Сбор товаров» в разделе Actions), обычно 2–5 минут. Результаты сохраняются в этот репозиторий, и сайт показывает их через минуту после окончания сбора.

**Вход для запуска сбора.** Нужен ключ GitHub, один раз на браузер:
1. https://github.com/settings/personal-access-tokens/new под аккаунтом takedown-desing.
2. Repository access: Only select repositories → ruchki-parser.
3. Permissions → Repository permissions → Actions: Read and write.
4. Generate token, скопировать, на сайте нажать «Войти, чтобы собирать» и вставить. Ключ хранится только в этом браузере.

Соответствие разделов и прочие настройки источника пока меняются в локальной админке (ниже).

## Локальная админка

1. Скачайте репозиторий: `git clone https://github.com/takedown-desing/ruchki-parser.git`.
2. Дважды щёлкните **«Запустить.command»** в папке репозитория. При первом запуске macOS может спросить разрешение: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».
3. Откроется браузер с админкой: http://127.0.0.1:8765. Окно терминала не закрывайте, пока работаете.

Нужен только Python 3 (на Mac обычно уже есть). Библиотеки ставятся сами при первом запуске.

## Как пользоваться

**Добавить источник.** Вставьте адрес и нажмите «Добавить и собрать».

| Что вставили | Что делает парсер |
|---|---|
| Главную страницу сайта | Ищет фид товаров. Нет фида: идёт по карте сайта и собирает карточки товаров |
| Страницу раздела, бренда или поиска | Берёт товары из этого списка, листает страницы списка |
| Прямую ссылку на фид (yml, xml) | Читает фид сразу |

**Поля формы:**
- **Бренд для всех товаров**: если сайт продаёт один бренд, а в карточках его нет.
- **Отбор по слову**: из большого магазина взять только нужное, например «FIMET». Слово ищется в названии, бренде, разделе и адресе.
- **Сколько товаров**: 3 для пробы, 0 для всех товаров.
- **Склеивать цвета**: у многих магазинов каждый цвет — отдельный товар. Парсер собирает их в одну карточку модели с несколькими покрытиями, как устроен наш сайт.

**Собрать.** Кнопка «Собрать» у источника или «Собрать все». Внизу справа видно журнал сбора. По окончании страница обновится, а результаты сохранятся в репозиторий и отправятся в GitHub.

**Карточка источника.** Нажмите на название источника. Там:
- настройки, в том числе адрес фида вручную, если владелец сайта дал ссылку;
- сопоставление разделов: раздел у источника → раздел нашего сайта. Без сопоставления колонка «Раздел» в Excel пустая, и импорт не создаёт лишних разделов;
- история сборов и все собранные товары с фото, ценами и характеристиками.

## Что получается

```
output/
  все-товары.xlsx            общий файл по всем источникам
  <источник>/
    products.xlsx            Excel для загрузки на сайт
    changes.xlsx             что изменилось с прошлого сбора
    products.json            собранные данные
    history.json             история сборов
    images/                  фото 800×800 на белом фоне, как на сайте
data/
  sites.json                 источники и их настройки
```

**Excel для сайта.** Строка = одно покрытие. Строки одной модели идут подряд с одинаковым «Названием». Колонки: Название, Бренд, Раздел, Артикул, Покрытие, Артикул варианта, Цена, На складе, Фото, Краткое описание, характеристики «Х: …». Колонки «Источник: …» служебные: адрес товара у источника, его раздел и описание, все фото, путь к фото в репозитории. Сайт их пропускает.

Загрузка на сайт: админка ручкидлядверей.рф → «Excel / CSV: загрузка и выгрузка». Сначала с галочкой «Только проверить», затем по-настоящему.

## Как парсер ищет данные

1. **Фид.** Проверяет ссылки на фиды в коде главной и в robots.txt, затем около сорока типовых адресов разных платформ: Яндекс Маркет (YML), Google Merchant, 1С-Битрикс, OpenCart, Shop-Script, MODX, WooCommerce, Shopify. Понимает форматы YML, Google Merchant, произвольный XML с товарами, JSON Shopify и WooCommerce.
2. **Страницы.** Если фида нет, берёт адреса из карты сайта или ссылки со страницы списка. Из карточки товара сначала читает разметку для поисковиков (JSON-LD, microdata, Open Graph), а если её нет, ищет заголовок, цену, артикул, галерею, таблицу характеристик и хлебные крошки по типичным признакам вёрстки.

Парсер ходит вежливо: одна страница в секунду, один поток. Скачанные страницы кэшируются на 6 часов в папке `cache/`, она в репозиторий не попадает.

## Без интерфейса

```bash
.venv/bin/python cli.py list                         # источники
.venv/bin/python cli.py add https://site.ru/ --limit 3
.venv/bin/python cli.py run                          # собрать все
.venv/bin/python -m pytest -q tests                  # проверки
```

3. **Браузер.** Если сайт достраивает страницу скриптом и обычной загрузкой фото не находятся, парсер сам открывает страницы в браузере без окна, как это делает посетитель. Настройка источника «Браузер для сайтов на скриптах»: сам решает, всегда, никогда.

## Когда сайт не собирается

Парсер не молчит и не отдаёт пустой Excel. Он останавливает сбор и пишет причину в списке источников и в карточке источника:

| Причина | Что делать |
|---|---|
| Сайт закрыт для посетителей из России (региональная блокировка) | Файл или фид от поставщика либо сбор через прокси нужной страны |
| Защита Cloudflare, капча, проверка «вы не робот» | Файл или фид от поставщика |
| Сайт запрещает доступ (403), слишком много запросов (429), ошибка сервера, не отвечает | Попробовать позже, проверить адрес |
| Адрес не существует (404) или сайт не найден | Проверить ссылку |
| Фото показаны в 3D-просмотрщике во встроенном окне | Фото у дилера или у поставщика |
| Карточки есть, но фото не видно даже в браузере | Фото у дилера или у поставщика |
| Каталог выложен в PDF, карточек нет | Файл от поставщика |
| На сайте не найдено ссылок на карточки | Вставить адрес раздела каталога вместо главной |
| Поиск по сайту ничего не дал | Проверить слово поиска или дать адрес раздела |

Если товары собраны, но чего-то не хватает у всех (цен, фото, раздела), в карточке источника появляются замечания.

Фото и тексты чужих сайтов принадлежат их владельцам. Описание по умолчанию не ставится в карточку, только в служебную колонку.
